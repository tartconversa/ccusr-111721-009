# 跨机构数据协作台账

本服务记录数据来源、字段含义、合作许可、数据产品及交付凭据。合作方可在本地演练不同机构和法域之间的资料流转；示例记录均为虚构，不连接真实口岸或支付系统。

需要 Python 3.10 或更新版本，不依赖第三方包。

运行项目测试：`python -m unittest discover -s tests -v`。
检查源码：`python -m compileall -q exchange`。
演练入口：`python -m exchange --database demo.db`。

领域逻辑分布在来源目录、合作许可、产品编排和交付核验中。`exchange/service.py` 组合这些操作，`exchange/db.py` 保存本地 SQLite 表结构；调用接口和现有边界可从源码及测试读取。

## 规则修订与影响预览

跨境规则调整不直接改写当前生效规则，而是经 `service.staging` 走从待发布到发布的流程：

1. `propose` 把规则修订登记为待发布状态，不影响在途交付；同一规则键的新修订会取代旧的待发布修订。
2. `preview` 基于来源血缘（产品 → 记录 → 来源）和许可关系计算影响预览，列出将失去或获得领取资格的数据产品与接收方及原因，并把所依据的来源、许可与规则事实存入快照。
3. `changes` 随时对比快照与当前数据，指出期间发生的变化原因（如来源停用、许可撤销、许可过期、规则被他人改动）。
4. `publish` 重新核对预览所依据的数据：若快照已过期则拒绝发布（`StalePreviewError`），过期预览不会被当成已发布结果；核对通过才把决定写入生效规则。

发布成功后，后续交付凭据的 `policy_revisions` 会固定实际生效的规则键与版本，可经 `staging.get` 回溯到对应的待发布修订与影响预览。
